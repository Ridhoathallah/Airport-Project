# Datasets — people detection (single class: `person`)

This directory holds the **data** side of the project: curated images,
human-reviewed annotations, versioned manifests, validation reports and the
metadata catalog. It is owned by the ML data engineering workstream and is
completely independent of the runtime monitoring database.

## Layout

```
datasets/
├── people_v1/                  # one dataset version
│   ├── data.yaml               # YOLOv5 entry point (generated by build_dataset.py)
│   ├── images/{train,val,test}/
│   └── labels/{train,val,test}/
├── manifests/                  # versioned JSON manifests (source of truth)
├── reports/                    # validation reports (JSON) and preview renders
├── metadata/                   # SQLite metadata catalog (generated, not committed)
└── collected/                  # machine-proposed hard examples awaiting review
```

`datasets/people_v1/` ships **empty**. No real imagery exists in this
repository yet: `input/` contains no source footage, so no dataset could
be curated without inventing data. The structure, the tooling and the
validation are in place; the pictures are still to come.

## Annotation format

YOLOv5 detection format, one row per object:

```
<class_id> <x_center> <y_center> <width> <height>
```

* `class_id` — integer. The class schema is **single-class**: `0 = person`,
  matching the COCO class the runtime consumes
  (`PERSON_CLASS_ID = 0` in `app/detect_people.py`).
* coordinates are **normalised to [0, 1]** relative to the image width and
  height, and describe the box *centre* and *size*, not the corners.

An **empty label file** means "this image was reviewed and contains no
person". That is a valid, meaningful annotation, not an error. It is only
treated as a reviewed negative when the manifest records
`annotation_status = negative_reviewed`; an undeclared empty label is
reported as a warning so a human decides.

## Source groups (leakage control)

Frames captured from the same video or recording session must not be
spread across `train` / `val` / `test`. Put them in a sub-directory:

```
datasets/people_v1/images/train/session_2026_10_20_a/frame_0001.jpg
```

The directory name becomes the **source group**, and the splitter keeps
every frame of a group in the same split.

## Rules

* Never hand-edit a manifest. Rebuild it with `scripts/build_dataset.py`.
* Never copy a model prediction into a label file. Machine output is
  `machine_proposed` and needs a human before it can become ground truth.
* Never commit the metadata catalog or collected frames — both are in
  `.gitignore`; the catalog is derived state and the frames may contain
  identifiable people.

## Commands

```bash
# create the metadata catalog (idempotent, safe to re-run)
venv/bin/python scripts/catalog.py init

# validate what is there right now
venv/bin/python scripts/validate_dataset.py --root datasets/people_v1

# build a new version: validate -> split -> manifest -> catalog
venv/bin/python scripts/build_dataset.py --root datasets/people_v1 \
    --name people_v1 --seed 20261020 --ratios 0.7/0.2/0.1

# check that a dataset is ready to train (runs no training)
venv/bin/python scripts/train_person.py --data datasets/people_v1/data.yaml \
    --weights models/yolov5s.pt --dry-run

# inspect the catalog
venv/bin/python scripts/catalog.py stats
venv/bin/python scripts/catalog.py datasets
```

`people_v1` is currently **empty** — there is no source footage in this
repository. Building it is refused with exit code 3; `--allow-empty`
registers it explicitly as an `empty` (not training-ready) version.

A synthetic fixture for smoke-testing the training plumbing (never real
data, and it refuses to write inside `datasets/`):

```bash
venv/bin/python scripts/make_synthetic_fixture.py --out /tmp/ml-fixture --images 24 --seed 7
```
